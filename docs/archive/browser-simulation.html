BLUEPRINT — NOT A RUNNING SERVICE
HEIMDALL A clear, local security overview for your home server and NAS.

Collect selected events, understand why they matter, and decide what to do next. Heimdall is planned for home systems where a full SOC stack would be too much to operate.

// HOME-FIRST, LOCAL-FIRST

Heimdall is a planned security assistant for NAS devices, routers, and a small number of home-hosted services. It brings selected events into one local view, groups related activity, explains the rule that raised an alert, and keeps a searchable history.

THE PRODUCT PROMISE

A clear, local security overview for a home server or NAS, without running a full SOC stack. Default processing stays on the home system. External lookups are optional. The owner remains in control of device and network changes.

NAS / ROUTER / SERVICE │ selected syslog events ▼ parse → normalize → local rules → grouped, explained alert ├── SQLite history ├── local dashboard ├── optional indicator lookup └── optional notification recommendation → owner reviews → owner chooses what to do

01. WHY HEIMDALL?

Home NAS products already include security checks, and focused tools already cover intrusion detection or broad endpoint monitoring. Heimdall’s intended value is a lightweight cross-device view that makes selected events understandable to a home owner.

ToolGood atHeimdall's intended role
NAS built-in securityChecking that vendor's device and settings.Bring selected events from more than one home system into one view.
WazuhBroad SIEM/XDR monitoring with central services and agents.Offer a narrower home-server experience with fewer services to operate.
CrowdSecDetecting known attack patterns and optionally enforcing decisions.Potentially consume its alerts and explain related activity for the owner.
TheHive / DFIR-IRISManaging investigations and collaboration for response teams.Keep a simpler personal alert history.
ShuffleConnecting tools into security automation workflows.Send optional notifications without requiring a workflow platform.

Heimdall is only worth choosing if setup, explanations, and home-wide context are easier than assembling the existing tools yourself. It complements NAS security features; it does not replace them.

02. VERSION ONE

FeatureFirst-release behavior
Event intakeReceive syslog from one selected NAS or router format.
Useful local rulesStart with repeated failed logins and suspicious login sequences.
Explainable alertsShow matched facts, rule, severity, source device, and related events.
Noise controlGroup repeats and apply configurable quiet periods.
Local historyStore events, alerts, and bounded enrichment results in SQLite.
NotificationsSend configured alerts through an optional notification provider.
Offline modeRun examples and local rules without internet access or API credentials.
Owner controlRecommend next steps; require owner action for changes to devices or network controls.
FIRST-RELEASE SAFETY BOUNDARY

No automatic firewall changes, account lockouts, file deletion, or device isolation. A detection is a signal to review, not proof of compromise.

06. BUILD ROADMAP

Phase 0 · Product contract

Choose a first NAS target, syslog format, normalized event shape, retention, and safe defaults.

Phase 1 · Local event pipeline

Receive, parse, normalize, and safely reject malformed events. Include offline examples.

Phase 2 · Rules and history

Add a few authentication rules, grouping, clear explanations, and SQLite persistence.

Phase 3 · Review and notify

Build the local alert view and add one optional notification provider.

Phase 4 · Optional enrichment

Add one provider with explicit opt-in, cache, timeouts, and rate limits.

Phase 5 · Home-lab evaluation

Measure resource use, retention growth, false positives, and supported log coverage.

07. CURRENT STATUS

DOCUMENTATION AND SIMULATION ONLY

The repository currently has a blueprint and browser demo. There is no live syslog receiver, detection engine, database, dashboard service, or notification provider yet.

Start with the technical blueprint, the evaluation guide, and the project glossary. The planned experience should be measured on modest hardware before publishing resource claims.
